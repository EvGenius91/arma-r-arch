Вся бизнес логика разбита на сервисы. Каждый сервис должен быть описан контрактом

### Контракты
Контракты лежат в директории Contracts.
Сервисы - Contracts/Services
Общие dto - Contracts/Dto
Общие enum - Contracts/Enums

Код в игре должен следовать этой архитектуре [[Architecture]], но в асинхронном режиме. Как бекенд принимает решение, а изменения в мире применяются через CommandBus: [[../Architecture/BackendGameMutation.md]]. 
Например есть метод для получения баланса getCash на бекенде он возвращает объект через return. 
В игре результат работы должен быть через callback который передается в аргументах метода.
Возвращаемые значения если это dto то должны хранится в контракте сервиса в директории Dto

### Код стайл
Для именования методов, классов следуем PascalCase. 
Для аргументов методов следуем camelCase
Для свойств класса следуем camelCase с префиксом m_{имя свойства}
Dto  должны быть иммутабельны. Т.е заполнение свойств через конструктор а получение данных через методы геттеры. Свойства должны быть private. Имя dto должно быть с суффиксом Dto {имя dto}Dto.
Свойства в дто тоже должны быть с описанием

### Описание кода
Все классы, методы, свойства должны иметь описание на русском
